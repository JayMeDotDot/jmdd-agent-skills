# C-RELNOTES

A link to the release notes, or the notes themselves, should be included in the crated-level documentation and/or the repository linked in Cargo.toml.

Breaking changes should be clearly identified in the release notes.

If using Git to track the source of a crate, every release published to crates.io should have a corresponding tag identifying the commit that was published. A similar process should be used for non-Git VSC tools as well.

Annotated tags are preferred because some Git commands ignore unannotated tags if any annotated tags exist.
